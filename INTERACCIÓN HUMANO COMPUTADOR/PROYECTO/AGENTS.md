# Instrucciones compartidas para asistentes de IA

Este proyecto es PROYECTO IHC, del equipo Wo bu zhi dao. Antes de analizar, editar o proponer trabajo, leer en este orden:

1. `README.md`
2. `docs/contexto.md`
3. `docs/requisitos.md`
4. `docs/decisiones.md`
5. `docs/estadoActual.md`
6. `docs/fuentes.md`
7. `docs/colaboracion.md`

Aplicar esas fuentes durante toda la tarea. Si no se puede acceder a alguna, declarar el límite y no sustituirla por una conversación recordada. F01 es la autoridad académica principal; no convertir propuestas de F07/F08 en requisitos. Los originales locales no son necesarios para comprender el contexto documentado y no deben publicarse.

La tarea actual es documentación y colaboración; no desarrollar la aplicación sin una nueva instrucción explícita. Distinguir requisitos docentes, acuerdos confirmados, hipótesis, propuestas y hallazgos verificados. No inventar participantes, citas, entrevistas, rasgos de personas, necesidades, permisos, aprobaciones o avances. No resolver silenciosamente contradicciones: usar el registro DEC. Las ideas existentes no son decisiones de diseño validadas.

No abrir, transcribir ni procesar grabaciones mediante IA sin verificar previamente el consentimiento específico. No publicar grabaciones, consentimientos firmados, transcripciones identificables, datos personales, credenciales ni documentos internos no autorizados. Mantener los originales intactos. No usar duración o nombre del audio para inferir contenido o participantes.

Actualizar el único documento responsable de cada tema y el estado al terminar; evitar duplicar contenido. Referenciar fuentes y evidencia, dejar explícitos los bloqueos y la revisión humana pendiente. No marcar tareas terminadas solo por haber generado un archivo.

Antes de cualquier operación de preparación o escritura Git, seguir íntegramente la sección Seguridad de Git de `docs/colaboracion.md`. No usar `git add .` ni `git add -f`. No hacer commit ni push sin autorización explícita; no modificar ni reescribir historial sin autorización. La carpeta está dentro de un repositorio superior: confirmar la raíz y limitarse al proyecto. No crear repositorios anidados ni cambiar remotos para solucionar permisos.

Al entregar, informar qué se cambió, cómo se verificó, qué no se pudo revisar y qué falta. No afirmar que se publicó o que la IA cargó reglas automáticamente sin comprobarlo.
